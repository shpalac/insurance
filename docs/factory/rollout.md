# Seven-phase public-repository rollout

1. **Bootstrap:** commit agent handbook, adapter config, public security policy and read-only static CI.
2. **Executable issues:** JSON Schema, validator, trusted ready-label transition and tests.
3. **Selective CI:** transitive impact calculation, immutable factory-gate and strict policy scan.
4. **Acceptance CI:** trusted-target execution without secrets, report verification, PR traceability.
5. **Integration:** independent review, squash auto-merge after branch protection, post-merge acceptance, audited multi-PR closure.
6. **Orchestration:** external LLM workers, independent GitHub App identities, fenced CAS leases, bounded repair, event+scheduled dispatch.
7. **Canary:** live happy-path, intentionally failed lint/test recovery, expired lease takeover, and no unauthorized merge. Enable low-risk automation only when all proofs pass.

Public visibility is intentional. No insurance customer data or secrets belong in the repo. Repository has no product toolchain yet, so adapter test/installation commands must be populated only after a product stack is chosen.
